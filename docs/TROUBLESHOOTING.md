# Troubleshooting

**Start with the log.** Every run writes `~/Library/Logs/Rosettus/<App>.log`. In Rosettus Launcher,
select the app and click *Show Log*. Crashes and hangs leave a report in
`~/Library/Logs/Rosettus/Reports/` with the PowerPC backtrace, the native backtrace and the last 16 KB
of the log.

| Symptom | What to do |
|---|---|
| The app opens and quits at once | Look in the log for `[exit] guest exit(n)` or `[trfatal]`. Some apps quit on their own when they find something they don't expect. To check, run the same app under the real Rosetta on Snow Leopard (`arch -ppc /path/App.app/Contents/MacOS/App`) and see whether it behaves the same there. |
| `install.sh`: *patches did not apply* | The export does not match the Snow Leopard build this release was made for (10.6.8 with Rosetta 1.0.x). `mismatch.txt` in the install folder lists the files that differ. |
| CFM apps (AppleWorks, Office 2004) quit at once; the log says `Launch failed with error code -2804 (cfragNoLibraryErr)` and `Error preparing app, -2804, <...><CarbonLib>` | The install has no resource forks: the export was copied in a way that dropped them. To check, run `xattr -l <root>/System/Library/CFMSupport/CarbonLib`; it should list `com.apple.FinderInfo` with type `shlb`. Re-export with `export_from_sl.sh` and reinstall, or run `tools/copy_forks.sh "/Volumes/<Snow Leopard disk>" <root>`. |
| Office 2004: *Microsoft Word cannot load the Microsoft Office shared libraries*, Entourage shows no window, Database Utility quits at once | Office keeps shared state in POSIX semaphores and shared memory named after your login session (`ShMemIntCrit<n>`, `PT_ShMemRef<n>`). An Office app that was force-quit or crashed leaves them behind, and the next Office app in the same session refuses to start. Rosettus removes these stale objects when an Office app opens them and no other Office app is running; the log then says `[shmem] removed stale Office ShMem objects`. If the error still appears, quit every Office app, including *Microsoft Database Daemon*, and open the app again. Logging out also clears them. `OAH_NO_SHMEMFIX=1` turns the cleanup off. |
| `install.sh` from an install-DVD export: *a different build; left unpatched* or a few thousand *different build* files | Expected: an install DVD carries different builds of some files than an updated Snow Leopard Mac. If it stops with *some patches did not apply*, the disc has a build of a patched file that this release has no patch for. Report the file named and the disc's part number. |
| `import_from_dvd.sh`: *could not run the Snow Leopard translator to decode it* | The 32-bit Intel translator from the DVD must run on this Mac (macOS 10.14 runs 32-bit code; 10.15 and later cannot). Check that the Rosetta packages were unpacked (`Rosetta.pkg` in the updates folder). |
| A game (Build-a-lot 2) stops at its first logo screen with full CPU, and a restart of the Mac fixes it | The game's millisecond clock stops after 24.8 days of uptime. Rosettus works around it on a Mac up for 12 days or more; check that `OAH_NO_UPTIMEFIX` is not set. Starting the app with `OAH_UPTIMEFIX_LOG=1` logs `[uptime]` when the workaround is on. |
| GoLive CS2 or InDesign CS2 hangs at start (no window, full CPU); the log says *spin lock ... neither locked nor unlocked. The memory has been smashed* in `CFPasteboardCreate` | The translated pasteboard server is in a bad state. Rosettus restarts it by itself when a pasteboard call has waited 20 s (`[pbwatch]` in the log). To restart it by hand, run `pkill -f usr/sbin/pboard` (it starts again on demand), then open the app again. Please report what was copied before it happened. |
| A PowerPC app uses more memory the longer it runs | Usually this is the app's own heap. Add `OAH_MEMSTATS=60` to the app's launcher (`Contents/Resources/rosetta.env`) to log the guest malloc totals and the resident size every minute. If the guest's "in use" figure grows along with the resident size, the app itself is using the memory. For example, Word 2004 keeps about 50 KB per document opened and closed. |
| AppleWorks 6 crashes opening an RTF file saved by TextEdit (or another current app) | AppleWorks' RTF translator cannot handle the long control words of current RTF (a stack overrun in its own code). Save the file as RTF from an older app, or as plain text or Word format. The crash ends the app at once and leaves a report. |
| `export_from_sl.sh`: *could not dump translate* | Rosetta is not installed on the Snow Leopard Mac: open **Install Rosetta.app** and accept the download. |
| No sound | Set `OAH_AUTRACE=1` and check the log. Check the output device in System Preferences > Sound. |
| A window is blank or black | For OpenGL apps, set `OAH_GLERR=1`. For other apps, try `OAH_NO_GTB=1` once and compare. |
| Copy/paste between PowerPC and Mac apps fails | Check the pasteboard agent: `launchctl list \| grep rosetta` should list `com.rosettus.ppc.pboard`. To reload the agents, reinstall (`./install.sh --update`). |
| "You need an administrator password" prompt does not appear | It is a normal macOS prompt; it may be behind other windows (look in the Dock). |
| A PowerPC app's dialog covers other apps | Window levels follow activation; report the app. |
| Opening an app that is already running (Finder, Spotlight, `open`) does not bring it to the front | The app takes the reopen event and usually comes forward. If it stays behind, click its Dock icon. |
| A PowerPC app's helper command or script fails (*Bad CPU type in executable*, an installer step *exited with status 5*) | Rosettus runs helper commands (NSTask, `posix_spawn`, `system`) and shell scripts started by PowerPC apps, and sends any PowerPC program they run back through Rosettus. `OAH_SPAWNTRACE=1` logs each spawn. Messages printed by PowerPC command-line tools go to `~/Library/Logs/Rosettus/tools.log`; `OAH_TOOL_STDERR=1` keeps them on the terminal. |
| An X11 app (Wireshark 1.x, GTK apps) says *cannot open display* | Install [XQuartz](https://www.xquartz.org) 2.7.11, then log out and back in once so `DISPLAY` is set. Rosettus maps `/usr/X11` to the PowerPC X11 libraries in its install folder. |
| A copy in Hex Fiend (or another app that copies lazily) does not reach Mac apps | Data an app only promises is not read, because reading it would run the app's own code inside the sync. `OAH_CLIP_PROMISED=1` turns this off for one app. |
| An app quits during start-up with `translate fatal(2 ...) (allocator object ...)` in its log | This happens occasionally after many force-quits in a row; open the app again. |
| SimCity 4 says it *will run with the software driver when next launched* | A previous start of the game was killed. Click OK, open it again, and choose **Play in a Window** in its Preferences if full screen fails. |
| An installer says *The software to be installed requires Administrator or higher level access privileges* | Run it from a normal login (Rosettus Launcher or a double-click), not over ssh. It asks for the administrator password with the macOS prompt, then restarts itself as root. From Terminal, `sudo launchctl asuser $(id -u) /Library/Rosettus/rosettus /path/Installer` starts it as root in your login session. `OAH_AUTHTRACE=1` logs the authorization calls. |
| *rosettus: … is a Classic Mac OS 9 application* | The app links InterfaceLib (Mac OS 9) instead of CarbonLib. Mac OS X ran these apps only in the Classic environment, which Rosetta never had. Use a PowerPC Mac OS 9 emulator (SheepShaver, QEMU). |
| *This application requires … thousands of colors* (Kid Pix Deluxe 4 or another app that checks the screen depth) | Mojave has 32-bit display modes only. Rosettus sets `OAH_GD_DEPTH=16` for Kid Pix Deluxe 4, which reports a 16-bit main screen to the app; windows keep 32-bit pixels. For another app, start it with `env OAH_GD_DEPTH=16 /Library/Rosettus/rosettus /path/App.app`. |
| Clicks stop reaching any PowerPC window after using Dashboard | Dashboard can leave its full-screen windows over the desktop. Press F12 (or open Dashboard and close it with Esc), or run `killall Dock`. |
| An InstallerMaker installer (StuffIt 7) fails | StuffIt 7's installer must run as root, because it writes to `/Library/Frameworks`. |
| Disc image *There may be a problem with this disk image* (hybrid CD images) | Run `hdiutil attach -nomount -noverify image.iso`, then mount its Apple_HFS partition with `mount -t hfs -o rdonly /dev/diskNs2 /some/folder`. |
| Java 1.3.1 or 5.0 prints *update_sharing command failed to execute*, Java 1.4.2 *HotSpot not at correct virtual address. Sharing disabled.* | Harmless: the JVM starts without its shared class archive. The program runs. |
| *dyld: Symbol not found: _CTFontGetGraphicsFont* (a Swing or AWT program under Java 5) | Java 5's AWT calls a CoreText function that Snow Leopard renamed. `install_java.sh` points the AWT library at Rosettus' `libjavashim`, which provides it. Run `install_java.sh` again if the Java files were copied in by hand. |
| Java 1.4.2 prints *JavaAWT: Assertion failure: token->inNativeMethod* | Harmless. |
| `rjava: no PowerPC Java ... installed` | PowerPC Java is an optional add-on. Double-click **Import PowerPC Java.command** in `/Applications/Rosettus/PowerPC Java Import`. On a PowerPC Mac with Tiger or Leopard, you can instead run `export_java_from_tiger.sh` from the Snow Leopard Export Kit, copy the archive over, and run `/Library/Rosettus/tools/install_java.sh` on it. |
| A PowerPC Java program crashes (`CRASH ... sig=10` or `sig=11` in the log) where it should throw `NullPointerException`, or a larger Java program crashes after starting (Minecraft) | Known issue. The PowerPC JVM handles some memory faults itself (null checks, its safepoint page), and those faults are not handed back to it under translation. Programs that do not hit such a fault run. |
| Version Cue CS2 is missing after a CS2 install, or its System Preferences pane does not open | Open Rosettus Preference Pane Viewer from Applications: it detects the installed PowerPC Adobe pane, and Other… selects a pane by hand. Install the optional PowerPC Java and the [Version Cue service](VERSION_CUE.md). If the pane reports the server as unavailable, check `/Library/Rosettus/versioncue/versioncue status` and `/Library/Logs/Rosettus/VersionCue-service.log`. |
| High CPU while idle | Some old apps poll; compare with Snow Leopard. Rosetta itself wakes about 15-25 times a second per app while idle. |
| A video app finds no camera, or its picture stays black; a recording app records silence | macOS asks once per app for the camera and the microphone: answer OK, or allow the app later in System Preferences > Security & Privacy > Privacy > Camera / Microphone. `rosettus` started from Terminal does not open the camera until permission has been given (the log says so). |
| A PowerPC app cannot read a saved password, or macOS asks whether *rosettus-kc* may use a keychain item | Item data goes through Rosettus' helper `rosettus-kc`. Items a PowerPC app saves trust it; an item saved by another app asks once (Allow / Always Allow). |

## Reporting a problem

Include:

* the app's name and version;
* the log;
* the report from `Reports/`, if there is one;
* the `Telemetry/<app>.<pid>.tsv` file, which lists the unbridged system calls the app made.
